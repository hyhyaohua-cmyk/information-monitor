# 新闻链接监控

项目恢复、版本关系和长期维护方法见 [`项目维护说明.md`](项目维护说明.md)。

这是一个只在本机运行的新闻链接发现工具。它会检查配置中的首页，自动发现网页公开声明的 RSS/Atom，以及 `robots.txt` 中公开的 sitemap；也支持显式配置 sitemap。

## 启动

需要 Python 3.9 或更新版本，不需要安装第三方依赖。

macOS 用户可以直接双击 `新闻监控工具.app`。启动器会在后台启动服务并打开浏览器；重复双击不会启动多个服务。需要关闭后台服务时，双击 `停止新闻监控.app`。

也可以使用终端启动：

```bash
python3 app.py
```

然后打开 <http://127.0.0.1:8765>，点击“手动刷新”。

## 处理规则

- 每个“网站 × 通道 URL”独立保存基线。
- 通道首次成功抓取时只记录现有链接，不报告新增。
- 抓取超时、HTTP 错误或解析失败不会建立基线；恢复后的首次成功仍只建立该通道基线。
- 从第二次成功抓取开始，该通道未见过的链接才有资格进入报告。
- 报告按规范化后的链接永久去重；追踪参数和 URL 片段会被移除。
- 每次刷新的新增报告按批次保留 3 天，界面按准确的刷新日期时间列出批次，也可查看保留期内的全部历史。
- 新增报告支持同时勾选多个网站，并与刷新批次和关键词组合筛选。
- 手动刷新时会实时显示当前阶段、完成通道数、百分比和累计耗时；刷新记录会保留每次实际耗时。
- 超过 3 天的报告、刷新批次、运行日志和升级备份会自动清理。已报告链接仅保留紧凑指纹，历史删除后仍不会重复报告。
- 如果链接路径或查询参数中含有可识别的完整日期或年月，只要符合北京时间当天或美东时间当天中的任意一个就会保留；同时不属于两个时区当天窗口的链接不会显示。
- 雅虎财经和 BigGo Finance 的 `/quote/股票代码` 行情详情页属于导航链接，不会进入新增报告。
- 新增报告会显示中文标题、网页原标题和原始链接。缺少标题时优先从链接中的文章路径提取；网址无法生成标题时才尝试读取文章页面。翻译结果会写入数据库缓存。
- 标题补充会持续处理到待办队列清空；缺少原标题时优先从网址路径提取，只有网址无法生成标题时才读取文章页面。
- 翻译遇到临时连接中断时会自动重试并切换备用地址；标题中的长数字前缀和随机编码后缀会在翻译前清理。
- RSS/Atom 条目包含发布时间时，只接收北京时间或美东时间当天联合窗口内的内容；滞后的订阅旧文章不会进入报告。
- 标题翻译时会同时读取源语言识别结果，只保留英语内容；西班牙语、法语、中文等非英语页面不会进入报告。
- sitemap index 的子 sitemap 仍会独立建立基线，但每个网站最多保留 8 个 sitemap；工具优先选择新闻、最新和当前日期相关的通道，避免遍历庞大的历史归档。每个 sitemap 最多读取 10,000 个地址。

状态保存在 `news_monitor.sqlite3`。若确实需要从零开始，可先停止服务，再自行备份并移走这个数据库文件。

## 边界

部分网站会要求登录、启用 JavaScript、验证地区或拦截自动访问。界面的“通道详情”会保留最近一次错误；这些失败不会破坏其他通道的基线，也不会制造误报。

## GitHub Actions 版

仓库内置 `.github/workflows/news-monitor.yml`。在 GitHub 的 **Actions → 刷新信息监控 → Run workflow** 中选择“新闻、智库或央行”即可手动刷新。

工作流会下载最近一次保存的 SQLite 状态，保持各通道基线和跨次去重；运行结束后将新状态保存为 Actions artifact、自动删除更旧的状态备份，并把近3天报告发布到 GitHub Pages。首次运行某个类别时只建立该类别基线。

首次使用前，在仓库 **Settings → Pages → Build and deployment → Source** 中选择 **GitHub Actions**。建议使用私有仓库；不要提交本地的 `news_monitor.sqlite3`。
